# ADR-0009: その場の方針・検討メモを GitHub Issue に移す

- ステータス: Accepted
- 日付: 2026-08-02
- 決定者: プロジェクトオーナー
- 関連: [ADR-0002](0002-documentation-structure.md)（本 ADR が notes 層に関する決定を置き換える）, [ADR-0005](0005-publish-as-oss.md), [ADR-0008](0008-code-as-source-of-truth.md)

## 背景と課題

[ADR-0002](0002-documentation-structure.md) は暫定メモを `docs/notes/` に置き、
確定したら spec / adr へ昇格させ、元のメモを `archive/` に移す運用を定めた。

しかしこの運用には無理がある。

- **捨てる前提の資料が git 履歴に永久に残る。** archive はゴミ箱として肥大化する。
- 昇格・棚卸しが手作業であり、放置されたメモが「古い方針」として残る。
  [ADR-0008](0008-code-as-source-of-truth.md) と同じ問題 —— 信用できない文書は無いより悪い。
- メモは本来「議論して、決めて、閉じる」もので、ファイルにはその状態機械が無い。

[ADR-0005](0005-publish-as-oss.md) で OSS 公開を決めたため、GitHub の Issue が使える。
Issue には open / closed という状態があり、議論のスレッドが付き、
閉じれば一覧から自然に消えて履歴には残る。**捨てる資料の置き場所として正しい形をしている。**

## 決定

**その場の方針・検討メモ・調査ログ・保留中の論点は GitHub Issue に置く。**
`docs/notes/` は廃止する。

| 資料 | 置き場所 | 寿命 |
| --- | --- | --- |
| 検討中の論点・調査ログ・その場の方針 | **GitHub Issue** | 閉じたら終わり |
| 決定と却下案 | `docs/adr/` | 永続 |
| 基本設計・ガイドライン | `docs/spec/` | 維持・メンテ |

運用ルール:

- 論点が生じたら Issue を立てる。ラベルで種類を分ける（`question` / `research` / `decision`）。
- 決着したら **ADR を起票し、Issue に ADR へのリンクを貼って閉じる。**
  Issue の本文を仕様書に転記しない。
- エージェントは `gh issue list` / `gh issue view` で読み書きする。
  ローカルから参照できるため、[ADR-0002](0002-documentation-structure.md) が
  外部ツールを却下した理由（エージェントが読めない）は当たらない。

## 検討した選択肢

### 案 A: GitHub Issue に移す（採用）

- 利点: open / closed の状態を持つ。議論が Issue に紐づく。
  閉じれば視界から消え、リポジトリが汚れない。`gh` CLI でエージェントも読める。
- 欠点: リポジトリのクローンだけでは全文脈が揃わない。
  GitHub に依存する（移行時は Issue のエクスポートが要る）。

### 案 B: `docs/notes/` を維持する

- 却下理由: 捨てる前提の資料が永久に履歴に残り、棚卸しが手作業になる。

### 案 C: メモを一切残さない

- 却下理由: 検討の途中経過が失われ、同じ調査を繰り返すことになる。
  特にエージェントはセッションをまたいで記憶しないため損失が大きい。

## 決め手

**リポジトリの清潔さを得るために、単一リポジトリでの自己完結性を捨てた。**

## 影響

- ドキュメントへの影響: `docs/notes/` を削除。`capture-note` スキルを
  `capture-issue` に置き換える。`docs/README.md` / `CLAUDE.md` を更新する。
- 運用への影響: **GitHub リポジトリの作成が前提になる。**
  作成までは既存の論点メモを移行できないため、
  `docs/notes/` は移行完了まで残し、新規追加のみ禁止する。
- 取り消す場合のコスト: 中。Issue の内容をファイルに戻す手作業が発生する。
