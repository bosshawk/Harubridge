# ADR-0005: OSS として公開する

- ステータス: Accepted
- 日付: 2026-08-01
- 決定者: プロジェクトオーナー
- 関連: [ADR-0003](0003-agent-driven-development.md), [ADR-0004](0004-defer-tech-stack-decision.md), [docs/spec/constraints.md](../spec/constraints.md)

## 背景と課題

[overview.md](../spec/overview.md) の未解決事項として「公開範囲（個人利用のみ / OSS 公開）」が
残っていた。この選択は以下に波及するため、技術構成の検討より前に決めておく必要がある。

- ライセンスの要否と選定
- リポジトリの可視性、および秘密情報・プレイヤーデータの扱いの厳格さ
- 非公式ツールであることの表明と免責の書き方
- 不具合報告や貢献を受け入れるかどうか
- ドキュメントを第三者が読む前提で書くか、自分たちだけが読む前提で書くか

なお、対象ユーザーは「自分と身近な数人」規模と想定されており
（[overview.md](../spec/overview.md) §2）、公開＝利用者拡大を目指すことではない。

## 決定

本プロジェクトを **OSS として公開する**。リポジトリは public とし、
ソースコードとドキュメント、およびコミット履歴を第三者が閲覧できる状態にする。

ライセンスの選定と公開開始の時期は、本 ADR では決めない（未解決事項）。

## 検討した選択肢

### 案 A: OSS として公開する（採用）

- 概要: リポジトリを public にし、ライセンスを付けて配布する。
- 利点:
  - 艦これの API 構造は非公開であり、この種のツールは先行 OSS の観測知見に依存せざるを得ない。
    受け取るだけで何も返さない立場は持続的でない。
  - エージェントが生成したコードを第三者が読む前提になり、品質の下限が上がる
    （[ADR-0003](0003-agent-driven-development.md) の体制では、人間の常時レビューが薄くなりがちなため）。
  - 不具合報告という形で、自分たちの環境以外での動作情報が得られる。
- 欠点:
  - 秘密情報・プレイヤーデータの混入が即座に事故になる。履歴からの完全削除は事実上不可能。
  - 非公式ツールとしての表明・免責を明示する責任が生じる。
  - サポート期待が発生しうる（応じる義務は無いが、方針の明示は要る）。

### 案 B: 個人利用のみ（private リポジトリ）

- 概要: 公開せず、自分と身近な範囲でのみ使う。
- 利点: 情報漏洩リスクが低い。ドキュメントを内輪の粒度で済ませられる。
- 却下理由: 上記の「先行 OSS への依存」に対して非対称であること、
  および第三者の目が入らないことでエージェント生成コードの検証機会を失うため。

### 案 C: 内部 private + 成果物のみ公開（ミラー方式）

- 概要: 開発は private リポジトリで行い、リリース物だけを別途公開する。
- 利点: 秘密情報の混入リスクを公開前に遮断できる。
- 却下理由: 二重管理のコストが高い。加えて、履歴とドキュメントが追えないため
  「第三者が検証できる」という案 A の主要な利点が失われ、公開する意味が薄い。

## 決め手

**非公開仕様に依存するツールである**という本プロジェクトの性質を重く見た。
先行する OSS の知見なしには成立しないため、公開して還元する側に立つ。
秘密情報の混入リスクは、運用ルール（[constraints.md](../spec/constraints.md) C-07）と
`.gitignore` で管理可能な範囲と判断した。

## 影響

- ドキュメントへの影響:
  - [constraints.md](../spec/constraints.md) に **C-07（リポジトリは公開されている前提で扱う）** を追加する。
  - [overview.md](../spec/overview.md) の未解決事項から「公開範囲」を削除し、
    ライセンス未選定を新たな未解決事項として残す。
  - README に非公式であることと免責を明記する（記載済み）。
- 実装への影響:
  - 認証情報・プレイヤーデータをリポジトリに残さないことが、努力目標ではなく必須要件になる。
  - 参照した OSS のライセンス表記を確認する義務が生じる。
- **取り消す場合のコスト: 高。** 一度公開したコミット履歴は取り消せない。
  したがって「公開前に一度、履歴に秘密情報が含まれていないか点検する」ことを
  公開開始の前提条件とする。
