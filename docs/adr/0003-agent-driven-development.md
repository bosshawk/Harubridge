# ADR-0003: 実装はすべて AI エージェントが行う

- ステータス: Accepted
- 日付: 2026-08-01
- 決定者: プロジェクトオーナー
- 関連: [ADR-0002](0002-documentation-structure.md), [CONTRIBUTING.md](../../CONTRIBUTING.md)

## 背景と課題

本プロジェクトのプログラムは、Claude Code / Codex などの AI エージェントによって
すべて作成する、という前提が最初から置かれている。
これは単なる「補助的にAIを使う」ではなく、開発プロセスそのものの前提であり、
リポジトリの構成・ドキュメントの粒度・レビュー方法に影響する。

この前提を明文化しないと、エージェントが「人間が読む前提」の慣習
（暗黙知に頼った薄いドキュメント、口頭で補われる仕様）を持ち込んでしまう。

## 決定

- 実装コードはすべてエージェントが生成する。人間の役割は
  **要求提示 / 意思決定 / レビューと受け入れ**に限定する。
- **docs-first**: 仕様に書かれていないものは実装しない。
  実装が先行した場合は、その差分を必ず spec に反映してから完了とする。
- エージェント共通の作業規約は [CLAUDE.md](../../CLAUDE.md) に集約し、
  反復する作業手順は `.claude/skills/` にスキルとして定義する。
- 出典の無い事実（特に艦これの非公開 API 仕様）を書かせない。
  推測には `TODO(要検証)` を必須とする。

## 検討した選択肢

### 案 A: エージェント前提を明文化し、ドキュメント駆動にする（採用）

- 概要: 上記のとおり。CLAUDE.md + skills + docs-first。
- 利点: セッションをまたいでも品質が安定する。
  複数のエージェント（Claude Code / Codex）で同じ規約を共有できる。
- 欠点: ドキュメント作成のコストが前倒しで発生する。

### 案 B: 規約を作らず、都度プロンプトで指示する

- 概要: タスクごとに必要な文脈を人間が書いて渡す。
- 利点: 初期コストがゼロ。
- 欠点: 同じ説明を毎回書くことになる。指示の揺れがそのまま実装の揺れになる。
- 却下理由: 継続的な開発では確実に破綻するため。

### 案 C: エージェントを特定の 1 種類（Claude Code のみ）に限定する

- 概要: `.claude/` 配下だけを整備し、他ツールは考慮しない。
- 利点: 設定が一本化される。
- 却下理由: Codex 等の併用が前提として示されている。
  ツール固有設定（`.claude/`）と、ツール非依存の規約（`CLAUDE.md` / `docs/`）を
  分離しておけば、どのエージェントでも同じ規約を読める。

## 決め手

エージェントは有能だが**文脈を持ち越さない**。
持ち越されない文脈をリポジトリ側に固定することが、この開発体制の中核である。

## 影響

- ドキュメントへの影響: `CLAUDE.md`、`docs/guides/agent-workflow.md`、`.claude/skills/` を新設。
- 実装への影響: 仕様書に要求 ID（`FR-xxx` / `NFR-xxx`）を振り、
  実装依頼とテストが ID で仕様を参照できるようにする。
- レビューへの影響: 人間のレビューは「仕様との一致」と「制約違反の有無」を主眼とする。

## 未解決事項

- テストの生成方針（どこまで自動生成に任せるか）は技術構成の決定後に検討する。
- Codex 側の設定ファイル（`AGENTS.md` 等）を置くかは、実際に併用を始める時点で判断する。
