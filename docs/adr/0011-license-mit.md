# ADR-0011: ライセンスに MIT License を採用する

- ステータス: Accepted
- 日付: 2026-08-02
- 決定者: プロジェクトオーナー
- 関連: [ADR-0005](0005-publish-as-oss.md)（未解決事項だったライセンス選定に決着をつける）

## 背景と課題

[ADR-0005](0005-publish-as-oss.md) で OSS 公開を決めたが、ライセンスは未選定のままだった。
ライセンスが無い状態は「作者の著作権が全面的に留保されている」ことを意味し、
第三者は法的に利用できない。公開の前に決める必要がある。

方針は「**一番ゆるいもの**」。利用・改変・再配布に極力制約をかけない。

## 決定

**MIT License** を採用し、リポジトリ直下に `LICENSE` を置く。
著作権表記は `Copyright (c) 2026 Harubridge contributors` とする。

なお本プロジェクトは艦これの非公式サードパーティ製ツールであり、
このライセンスは**本リポジトリのコードとドキュメントにのみ**及ぶ。
ゲーム側の権利物には一切関係しない（[constraints.md](../spec/constraints.md) C-05）。

## 検討した選択肢

### 案 A: MIT License（採用）

- 概要: 著作権表示とライセンス文の保持のみを条件に、あらゆる利用を許可する。
- 利点: **実務上「一番ゆるい」と言えば通常これを指す。** GitHub が自動認識し、
  他の OSS との組み合わせで問題が起きない。読み手も条件を説明不要で理解できる。
- 欠点: 著作権表示の保持義務が残る（完全な無条件ではない）。

### 案 B: 0BSD / Unlicense（パブリックドメイン相当）

- 概要: 著作権表示の保持すら求めない。文字どおり最も制約が少ない。
- 却下理由: 厳密には案 A より緩いが、採用例が少なく、
  利用者が「本当に使ってよいのか」を判断するのに一手間かかる。
  特に Unlicense は法的有効性への批判があり、CC0 は特許の扱いがコード向きでない。
  **ゆるさの差（著作権表示 1 行の保持）に対して、認知度の差が割に合わない。**

### 案 C: Apache-2.0

- 概要: 特許条項と貢献者からの特許ライセンス付与を含む。
- 却下理由: 明示的で安全だが条文が長く、「ゆるさ」の方針と合わない。
  本プロジェクトの規模で特許リスクを見込む理由も無い。

### 案 D: GPL-3.0

- 却下理由: 派生物にも同じライセンスを要求するため、方針と正反対。

## 決め手

**認知度を得るために、著作権表示 1 行ぶんのゆるさを捨てた。**

## 影響

- リポジトリ直下に `LICENSE` を追加する。
- `README.md` のライセンス節と、[overview.md](../spec/overview.md) の未解決事項を更新する。
- 今後、外部の OSS からコードを取り込む場合は**ライセンス互換性の確認が必要**になる
  （[constraints.md](../spec/constraints.md) C-07）。特に GPL 系のコードは取り込めない。
- 取り消す場合のコスト: **高。** 一度公開したバージョンに対して与えたライセンスは撤回できない。
  変更できるのは以後のバージョンのみ。
