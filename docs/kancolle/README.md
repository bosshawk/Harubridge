# 艦これ側の仕様（観測結果）

**外部システム（艦これ）がどうなっているか**を記録する場所。
[ADR-0020](../adr/0020-kancolle-reference.md) による。

> **ここは「我々の仕様」ではない。** 相手の仕様を観測して書き留めた記録である。
> 我々が決めたことは [`docs/spec/`](../spec/)、決めた理由は [`docs/adr/`](../adr/) にある。

## なぜ書くのか

[ADR-0008](../adr/0008-code-as-source-of-truth.md)（コードが正）は、
**自分たちの実装**についてのルールである。艦これ側の仕様には当てはまらない。

- コードには**我々が実装した範囲しか現れない**。観測して分かったことのほうが広い
- 艦これの仕様は**公式に公開されていない**（[C-03](../spec/constraints.md)）。
  ここに書かなければ、知識はどこにも残らない
- **ゲームのアップデートが無い限り変わらない。** 頻繁に古くなる類の文書ではない
- むしろ**変化を追いかけることに価値がある**。git の履歴がそのまま変更の記録になる

## 書き方のルール

### 1. 出典と観測日を必ず書く

**これがこの階層で最も重要な規律である。**

艦これの仕様は非公開であり、ここに書かれることは**すべて推定**である
（[C-03](../spec/constraints.md)）。根拠のない記述は、実装を誤らせる。

| 根拠の種類 | 書き方 |
| --- | --- |
| 自分で観測した | `観測: 2026-08-02` と、どうやって観測したか |
| 既存 OSS を参照した | リポジトリ名・ファイル・**ライセンス**・参照日 |
| 検証記事・wiki を参照した | URL と参照日 |
| 根拠が無い（推測） | **`TODO(要検証)` を付ける。書いてよいが、断定しない** |

計算式については [NFR-009](../spec/requirements.md) が出典の併記を必須としている。

### 2. 「いつ時点の話か」を書く

ゲームのアップデートで変わりうる。**観測した時点を明示する。**
更新するときは古い記述を消してよい（変更の経緯は git の履歴に残る）。

### 3. 事実だけを書く。我々がどう扱うかは書かない

- 書く: 「`api_port/port` は母港に戻るたびに全量が飛ぶ」（観測した事実）
- 書かない: 「最後の 1 件で上書きする」（我々の設計。→ [ADR-0021](../adr/0021-data-persistence.md)）

### 4. 網羅しようとしない

**必要になったものから書く。** 全エンドポイントを埋めることを目標にしない。
使っていない知識は検証されず、古くなったことにも気づけない。
