# ルール: 疲労度（コンディション）

- 最終観測: 2026-08-02
- 確度: **参照**（有志 wiki と OSS 実装の突き合わせ。自前の実測はしていない）

対応する要求: [FR-011](../../spec/requirements.md)（個艦の疲労表示）、
[FR-025](../../spec/requirements.md)（疲労回復の通知）

> 参照した有志 wiki 自身が「以下、詳細は**推定**なので間違いが含まれているおそれがあります」と
> 明記している。本ページの記述はすべて観測に基づく推定である（[C-03](../../spec/constraints.md)）。

## ルールの内容

### コンディション値

- 艦娘ごとに「コンディション値」（以下 cond 値）を持つ。**0 〜 100 の値を取る。**
- **cond 値そのものは画面に表示されない。** ゲーム画面では
  キラキラ表示・オレンジ／赤の顔アイコンとして段階的に示される。
- **cond 値の更新は「母港」画面を表示したタイミングでのみ行われる。**
  編成画面や改装画面を開いたままでは更新されない。
- 出撃中は 1 回の戦闘ごとに変動する。

### 表示の区分

| cond 値 | 表示 | 状態 | 公式用語 |
| --- | --- | --- | --- |
| 71 〜 100 | キラキラ（★10 個相当） | 戦意高揚状態 | 戦意高揚 |
| 58 〜 70 | キラキラ（★8 個相当） | 戦意高揚状態 | 戦意高揚 |
| 50 〜 57 | キラキラ（★6 個相当） | 戦意高揚状態 | 戦意高揚 |
| 40 〜 49 | （なし） | 通常状態 | — |
| 30 〜 39 | 「給」アイコンが点滅 | 軽度の疲労状態 | — |
| 20 〜 29 | オレンジ | 中度の疲労状態 | 疲労 |
| 0 〜 19 | 赤 | 重度の疲労状態 | 疲労困憊 |

キラキラの 3 段階表示は 2023/11/28 のアップデートで追加された。

**戦闘中の判定は母港での表示と一致しない。** 昼戦突入時に cond が -3、
夜戦突入時に -2 されるため、たとえば通常艦隊同士の昼開始マスでは
cond 53 以上でキラキラ判定、cond 32 以下でオレンジ相当の判定になる。

### 自然回復（本プロジェクトの争点）

- 自然回復は**リアルタイムには行われない。**
  「母港」画面以外から「母港」画面に戻った時に、前回の回復からの経過時間に応じて
  **3 分ごとに +3** 回復した結果が反映される。
- **上限は cond 49。** 自然回復だけでキラキラ状態（50 以上）になることはない。
- **回復するのは cond 49 未満の艦のみ。**
- 艦隊に編成したままでも、編成を解除しても回復する。
  **出撃中・演習中・遠征中・入渠中も回復は進む**（母港に戻ったときに反映される）。
- **回復のタイミングはサーバ時刻で判定されている。**
  母港画面を開いた時刻からカウントされるわけではない
  （12:00:00 に回復したなら次は 12:03:00）。
  つまり**全艦娘に共通の、3 分周期の固定した位相がある。**
- 有志 wiki の目安: 赤疲労が消えてから完全回復まで約 30 分、
  オレンジ疲労が消えてから約 21 分、「給」アイコンの点滅が消えてから約 9 分。

**位相はクライアントから直接は分からない。** 参照した OSS はいずれも、
観測した cond 値の変化から 3 分周期の位相を推定している。

- ElectronicObserver は位相の**下限と上限の区間**を保持し、
  観測のたびに区間を狭めていく（`ConditionPredictMin` / `ConditionPredictMax`）。
  初期値は「0 秒 〜 360 秒」、すなわち**最初は 3 分以上の不確かさがある**。
- KancolleSniffer は観測した cond 値の差分と経過時間の整合が取れないときに
  推定をリセットする（`InvalidateCond`）。

したがって、**「あと何分で回復するか」の予測は最大で 3 分程度ずれうる。**
「回復した」という事実そのものは、母港のデータを観測すれば確定する。

### 自然回復以外の変化

**回復側**

| 契機 | 変化 |
| --- | --- |
| 入渠の完了時 | cond 0〜39 → 40。40 以上なら変化なし（49 になるわけではない） |
| 「改造」（近代化改修ではない） | cond 0〜100 → 40。キラキラもリセットされる |
| 給糧艦「間宮」 | cond 0〜49 → 50（または 0〜39 → 40。表記が 2 通りある） |
| 給糧艦「伊良湖」 | cond 0〜40 → 65、cond 41〜99 → +25（上限 100） |
| 間宮・伊良湖の同時使用 | cond 0〜40 → 旗艦 70 / 随伴 65、cond 41〜99 → 旗艦 +30、随伴は条件により変動 |
| 戦闘糧食の発動 | +10 〜 +14（秋刀魚の缶詰は +12） |
| 緊急泊地修理の実施 | +7（イベント海域でのみ実施可能） |
| MVP 取得 | +10 |
| 旗艦ボーナス | +3（S 勝利〜C 敗北のとき。D・E 敗北では ±0） |
| 戦闘結果 | S +4 / A +3 / B +2 / C +1 / D・E ±0 |

**消耗側**

| 契機 | 変化 |
| --- | --- |
| 艦の入手時 | 40（ドロップ・建造を問わない） |
| 出撃帰投時 | -15。ただし**帰投時点の cond が 30 未満なら -30** |
| 演習帰投時 | ±0 |
| 昼戦突入 | -3。ただし**突入時の cond が 30 未満なら -9** |
| 夜戦突入 | -2 |
| 遠征帰投時 | -3（遠征時間に依らない）。結果確認時に cond 30 未満なら -9 |
| 交戦型遠征の帰投時（損傷艦） | -5? 〜 -10（ランダム、遠征帰投時の疲労に上乗せ） |
| 交戦 II 型遠征の帰投時（損傷艦） | -10 〜 -18?（同上） |
| 前衛支援任務の帰投時 | -1 〜 -5（ランダム） |
| 決戦支援任務の帰投時 | -1 〜 -10（ランダム） |
| 護衛退避 | 退避前の値によらず、退避した艦がともに cond 22 になる |

出撃中にエラーや誤操作でゲームが中断された場合、次回ログイン時に
帰投した扱いとなり、その時点で -15 される。

### 疲労が結果に効く場面

- **遠征**: 結果確認時にオレンジ・赤疲労（cond 29 以下）の艦が 1 隻でもいると**失敗する**。
  遠征中も時間経過で回復するため、出発時に赤疲労でも帰投時に回復していれば問題ない。
  なお「遠征帰投時の -3」はこの判定に含まれない。
- **遠征の大成功**: 艦隊の全員が戦意高揚（キラキラ）状態であることが条件。
  6 隻すべてキラキラなら 100%、5 隻なら約 95%、4 隻なら約 80% と見られている。
- **戦闘**: cond 33〜52 では明確なマイナス補正は確認されていない。
  cond 32 以下で命中率・回避率の低下が確認されている。
  cond 19 以下では轟沈ストッパーの挙動が変わり、大破しやすくなる。

### 基地航空隊の疲労は別系統

基地航空隊にも疲労があるが、**艦娘の疲労とは別の仕組み**である。
回復量は航空隊の状態（出撃／休息／防空／退避／待機）と基地の整備 Lv で変わる。

| 整備 Lv | 配置転換時間 | 3 分ごとの回復量（出撃 / 休息 / 防空 / 退避 / 待機） |
| --- | --- | --- |
| Lv0 | 12 分 | 1 / 8 / 2 / 3 / 4 |
| Lv1 | 10 分 | 1 / 10 / 2 / 3 / 4 |
| Lv2 | 8 分 | 1 / 12 / 3 / 4 / 5 |
| Lv3 | 6 分 | 2 / 12 / 3 / 4 / 5 |

**3 分周期であることは艦娘と共通**だが、回復量が異なる。

## 変動の条件

- **区分の境界は、母港表示と戦闘中で異なる。** 昼戦突入時 -3・夜戦突入時 -2 が
  戦闘の直前に適用されるため、「母港ではキラキラなのに戦闘では無疲労」という状態が起きる。
  さらに敵味方のいずれかが連合艦隊の場合、判定の順序が変わるという検証がある。
- **自然回復の位相**は全艦娘に共通で、サーバ時刻に固定されている。
  艦ごとに独立したタイマーがあるわけではない。
- キラキラの表示段階（50 / 58 / 71）は 2023/11/28 のアップデートで
  増えた。**表示の段階はアップデートで変わりうる。**

### 外部仕様への影響（判断は仕様側で行う）

[docs/spec/external/timers.md](../../spec/external/timers.md) は
「疲労が回復したと判定する基準と、回復までにかかる時間」が未検証であることを理由に、
**疲労回復の通知を既定で無効**としている。本ページで確認できた／できなかったことは次のとおり。

| 論点 | 状況 |
| --- | --- |
| 回復速度 | **確認できた。** 3 分ごとに +3、上限 49。3 つの独立した資料が一致 |
| 区分の境界 | **確認できた。** ただし母港表示と戦闘中で境界が異なる |
| 「回復した」ことの検知 | **可能。** 母港のデータを観測すれば cond 値が得られる |
| 「あと何分で回復するか」の予測 | **精度に限界がある。** 3 分周期の位相はサーバ側にあり、観測から推定するしかない。初回は最大 3 分程度ずれる |
| 何を「回復」と呼ぶか | **未決。** これは観測事項ではなく我々の設計判断 |

**既定値を変えるかどうかは仕様側の判断であり、このページでは決めない**
（[docs/kancolle/README.md](../README.md) の「事実だけを書く」）。
