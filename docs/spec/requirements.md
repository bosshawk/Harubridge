# 要求仕様

> ステータス: **ドラフト（オーナー承認待ち）**
>
> 既存ツールの機能調査（Issue #3）をもとに起こした一覧。
> **順次実装する前提で、優先度と実装状況をこの表で管理する。**

## 記法

- ID は `FR-nnn`（機能要求）/ `NFR-nnn`（非機能要求）。
  **一度振った ID は再利用しない**（削除した要求の ID は欠番のまま残す）。
- 優先度: `Must`（無いと成立しない）/ `Should`（あるべき）/ `Could`（あれば良い）
- 状態: `未着手` / `実装中` / `実装済` / `対象外`
- 実装依頼・外部仕様・テストは、この ID を使って要求を参照する。
- **状態の更新に承認は不要**（実装の進捗を反映する機械的な同期作業として扱う）。

## 方針

**統合型**を目指す。ゲーム画面の表示と情報の可視化を 1 つのアプリで完結させる
（Issue #3 の分類による）。計算系（D）も対象に含める。
