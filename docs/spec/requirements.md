## 記法

要求を書き始めるときのルール。

- ID は `FR-nnn`（機能要求）/ `NFR-nnn`（非機能要求）。
  **一度振った ID は再利用しない**（削除した要求の ID は欠番のまま残す）。
- 優先度: `Must`（無いと成立しない）/ `Should`（あるべき）/ `Could`（あれば良い）
- 状態: `TBD` / `確定`
- 実装依頼・外部仕様・テストは、この ID を使って要求を参照する。

## 制約との違い

[`constraints.md`](constraints.md) の `C-nn` は**制約**であり、要求とは別物。

- **制約**は「越えてはならない線」。要求が未作成でも既に有効。
- **要求**は「実現したいこと」。制約の範囲内で定義する。

制約に反する要求は立てられない。要求を作る際は先に
[`constraints.md`](constraints.md) を読むこと。
