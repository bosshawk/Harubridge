# 前提と制約

**実装・提案の前に必ず読むこと。** ここに書かれた制約に反する機能は、
要望があっても実装しない。覆すには ADR での明示的な決定が必要。

## C-01: ゲームプレイを自動化しない

- クリック代行・自動遠征・自動出撃・巡回など、**プレイヤーの操作を代替する機能は作らない**。
- ゲームサーバに対して、プレイヤーの操作に起因しないリクエストを送らない。
- 理由: 一般にオンラインゲームの利用規約で禁止される行為であり、
  アカウント停止のリスクをユーザーに負わせるため。本プロジェクトの価値は
  「情報の可視化」であって「操作の代行」ではない。

## C-02: 通信は読み取り専用として扱う

- ゲームとサーバ間の通信を**観測**することは行うが、**改変・再送・遮断は行わない**。
- リクエストの追加・リトライ・並列化もしない。通信量はゲーム本体と同一に保つ。
- 理由: 改変はチート行為に該当する。また負荷はサービス提供者への迷惑となる。

## C-03: 非公開仕様への依存であることを常に意識する

- 艦これの API 仕様は公式に公開されていない。本アプリが依存する構造は
  すべて**観測に基づく推定**であり、予告なく変わる。
- したがって:
  - 仕様書に API 構造を書くときは、**根拠（実測日 / 参照した OSS）を必ず併記**する。
  - 根拠が無い記述には `TODO(要検証)` を付ける。
  - 実装は、未知のフィールドや構造変化に遭遇しても**クラッシュせずに縮退動作**する。
- 理由: 推測を確定仕様として扱うと、エージェントが誤った実装を自信を持って生成するため。

## C-04: 取得したデータを外部に出さない

- プレイヤーのゲームデータ・認証情報・通信ログは**ローカルにのみ保存**する。
- 外部サービスへの自動送信・自動アップロードは行わない。
- ユーザーが明示的に操作したエクスポートのみ許可する。
- 認証情報（トークン等）はログに出力しない。ログ・スクリーンショットを保存する機能を
  作る場合は、認証情報のマスキングを実装の必須要件とする。

## C-05: 権利関係

- 本プロジェクトは非公式であり、権利者とは無関係である。
- ゲームの画像・音声・テキストなどの**アセットをリポジトリに含めない**。
  再配布もしない。
- 艦船名などの固有名詞を表示のために扱うことは許容するが、
  ゲーム由来のデータファイルを同梱しない。

## C-06: 開発体制上の制約

- 実装はすべて AI エージェントが行う（[ADR-0003](../adr/0003-agent-driven-development.md)）。
  そのため、**仕様書に書かれていない挙動は存在しないもの**として扱う。
- 人間のレビュー負荷を抑えるため、1 変更の粒度を小さく保つ。

## C-07: リポジトリは公開されている前提で扱う

> 根拠: [ADR-0005](../adr/0005-publish-as-oss.md)

- 本プロジェクトは OSS として公開する。**コミット履歴を含む全内容が第三者に読まれる。**
- したがって:
  - 認証情報・提督名・プレイヤー個人情報・通信ログを**一度でもコミットしない**。
    履歴からの完全な削除は事実上不可能であり、`git rm` では消えない。
  - 実測ログやスクリーンショットを資料として文書に載せるときは、
    識別情報とトークンを必ずマスクする。
  - ゲームアセットを含めない（C-05）。公開により侵害が明白になるため、より厳格に守る。
  - 参照した OSS のライセンス表記を確認し、必要な帰属表示を行う。
- ドキュメントは**第三者が読んで理解できる粒度**で書く。内輪の暗黙知に頼らない。
- 公開を開始する前に、履歴に秘密情報が含まれていないか一度点検する。
