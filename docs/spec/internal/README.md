# 内部仕様

**外部仕様をどう実現するか**を書く場所。モジュール構成・データモデル・処理フロー・
エラー処理・テスト方針。

> **外部仕様を変えない限り、エージェントの判断で更新してよい**
> （[ADR-0006](../../adr/0006-split-external-and-internal-spec.md)）。
> ただし変更が外部仕様に及ぶ場合は、そこで人間の承認が必要になる。

## 現在の状態

**空。** 内部仕様は技術構成に従属するため、
[ADR-0004](../../adr/0004-defer-tech-stack-decision.md) が解消されるまで原則として書かない。

技術構成が未決のまま内部仕様を書くと、特定の技術を前提とした記述になり、
選定を歪める。この段階では [`external/`](../external/) を先に書き進める。

## 書き方

- [`_template.md`](_template.md) を `<機能名>.md` にコピーして書く。
  ファイル名は対応する外部仕様と揃える。
- **ユーザーから見える振る舞いを再掲しない。** 外部仕様へリンクする。
  同じ事実を 2 箇所に書くと、必ず片方が古くなる。
- 艦これの API 構造を書くときは**根拠（実測日 / 参照 OSS）を必ず併記**する
  （[constraints.md](../constraints.md) C-03）。根拠が無ければ `TODO(要検証)`。
- 未知のデータに対する縮退動作を必ず書く（NFR-003）。
