# ドキュメント整合性の点検

エージェント駆動開発では、ドキュメントの矛盾がそのまま実装の欠陥になる。
定期的に点検する。

## 点検項目

### 1. ADR

- [ ] `docs/adr/README.md` の一覧に、`docs/adr/` の全ファイルが載っているか
- [ ] 番号に欠番・重複が無いか
- [ ] `Proposed` のまま長期間放置されている ADR が無いか（決めるか捨てるか）
- [ ] `Superseded by ADR-NNNN` の参照先が実在するか
- [ ] `Accepted` な ADR の内容が、あとから書き換えられていないか（git log で確認）

### 2. 仕様

- [ ] `requirements.md` の要求 ID に重複・再利用が無いか
- [ ] `external/` の仕様が参照する FR/NFR が実在するか、逆に参照されていない要求が無いか
- [ ] **コードを読めば分かることが文書化されていないか**（処理フロー・クラス構成・データ構造）
- [ ] `architecture.md` の記述が実装とずれていないか
- [ ] `external/` / `guidelines/` の各 README の一覧表が実ファイルと一致しているか
- [ ] `constraints.md` に反する記述が他の仕様に無いか
- [ ] 未確定箇所に `TODO(未確定)` / `TODO(要検証)` が付いているか
      （逆に、既に確定したのに TODO が残っていないか）
- [ ] 過去形・未来形の記述が混ざっていないか（仕様は現在形）
- [ ] 仕様で使われている用語が `glossary.md` に載っているか

### 3. 暫定メモ

- [ ] `docs/notes/README.md` の一覧と実ファイルが一致しているか
- [ ] `進行中` のまま 1 か月以上更新されていないメモが無いか
- [ ] `昇格済み` / `破棄` のメモが `archive/` に移動されているか
- [ ] 昇格済みメモの「昇格先」リンクが実在するか

### 4. 横断

- [ ] リポジトリ内の相対リンクが全て解決するか
- [ ] 同じ事実が 2 箇所以上に書かれていないか
- [ ] `README.md` の「現在の状態」表が実態と合っているか
- [ ] 実装がある場合、`docs/spec/` の記述と実装が一致しているか

## 実行方法

### リンク切れの検出

```bash
# Markdown 内の相対リンクを抽出して存在確認する
grep -rhoE '\]\(([^)#]+\.md)[^)]*\)' --include='*.md' . \
  | sed -E 's/^\]\(//; s/[)#].*$//' | sort -u
```

抽出したパスを、リンク元ファイルからの相対パスとして解決し、実在を確認する。

### TODO の棚卸し

```bash
grep -rn 'TODO(' --include='*.md' .
```

各 TODO について「まだ未確定か / もう確定したのに残っているか」を判断する。

### 放置メモの検出

```bash
git log -1 --format='%ad %an' --date=short -- docs/notes/<file>
```

`進行中` のメモの最終更新日を確認する。

## 報告の仕方

見つけた問題を**深刻度順**に並べて報告する。

| 深刻度 | 例 |
| --- | --- |
| 高 | 仕様と実装の乖離、制約違反、確定仕様に見える未確定記述 |
| 中 | リンク切れ、ADR 一覧の漏れ、重複記述 |
| 低 | 表記ゆれ、用語集の未登録 |

**勝手に直さない。** 高・中の問題は修正案を提示し、人間の判断を仰ぐ。
軽微なもの（リンク切れ、一覧の追記漏れ）は修正してよいが、報告に含める。
