# ADR 参照の隔離を点検する

## ルール（CLAUDE.md §3）

**`docs/adr/` の外から ADR を参照しない。** ADR は過去の経緯の記録であり、最新の資料ではない。
参照を許すと、ADR が無効になったときにリンクの張り替え漏れとコメントの陳腐化が必ず発生する。

| 種類 | 例 | 可否 |
| --- | --- | --- |
| 個別 ADR へのリンク | `[ADR-番号](docs/adr/…)` | ❌ |
| 番号での言及 | 「ADR-番号 §3 により」 | ❌ |
| 送り先としての言及 | 「経緯は ADR にある」「詳細は ADR 参照」 | ❌ |
| 手続きの説明 | 「決定は `docs/adr/` に記録する」 | ✅ |
| 書式の例示 | コミット規約の `docs(adr): ADR-NNNN …` | ✅（番号はプレースホルダにする） |
| `docs/adr/` の内側どうしの参照 | ADR 間の相互リンク・一覧 | ✅ |

## 検出

```sh
git ls-files | grep -v '^docs/adr/' | grep -v 'audit-adr-refs' \
  | xargs grep -nE 'ADR-[0-9]+|docs?/adr/[0-9]|adr/archive' 2>/dev/null
```

機械検出できない「送り先としての言及」は、上の grep に加えて次でざらいする
（誤検知を含むので目視で判定する）:

```sh
git ls-files '*.md' | grep -v '^docs/adr/' | grep -v 'audit-adr-refs' \
  | xargs grep -n 'ADR' 2>/dev/null
```

許可される残余は「決定を `docs/adr/` に記録する」という手続きの説明だけ。

## 直し方

**参照を消すだけで終わらせない。** 文が根拠を失って不明瞭になるなら、根拠そのものを書く。

| 違反の形 | 直し方 |
| --- | --- |
| `ルール X（[ADR-番号](…)）` | 括弧ごと削除。ルール X は自立して残る |
| 「ADR-番号 により X する」 | 「X する」に書き直す。理由が要るなら理由そのものを短く書く |
| 「経緯・根拠は ADR にある」 | 削除。読み手は `docs/adr/` の一覧から自分で辿れる |
| コード内コメント `// X する（ADR-番号）` | `// X する` に。番号ではなく**なぜ**を書く |
| 仕様書の「関連 ADR:」行 | 行ごと削除 |

- 生成物（例: `tsc` が出力する `.js`）に違反が残る場合は**ソースを直して再生成**する。
  生成物を手で編集しない
- 直したあと、検出コマンドを再実行して 0 件を確認する

## 使う場面

- ADR を書いた・Supersede した後（新しい番号を外に書いていないか）
- ドキュメント・コード・設定・スキルを書いた後
- `docs-audit` の一環として
