# 暫定メモを残す・畳む

`docs/notes/` は**捨てる前提**の場所。確定仕様ではない。

## A. メモを書く

### 1. ファイルを作る

- 場所: `docs/notes/YYYY-MM-DD-english-kebab-topic.md`
- `docs/notes/_template.md` をコピーする
- **状態ヘッダは必須**（`状態: 進行中` / `日付` / `昇格先`）
- 1 メモ 1 論点。長くなったら分ける

### 2. 書く

- **結論を急がない。** 分からないことは「分からない」と書く。
- 事実と推測を分ける。事実には出典（URL + 参照日）を書く。
- 人間の確認が必要なものは `TODO(要確認)` で明示する。
- **意思決定はしない。** 選択肢とトレードオフを並べ、推奨案を挙げるところまで。
  決めるのは人間（[docs/guides/agent-workflow.md](../../../docs/guides/agent-workflow.md)）。

### 3. 一覧を更新する

`docs/notes/README.md` の「現在のメモ」表に 1 行追加する。

### 4. コミットする

```
docs(notes): <日本語の要約>
```

## B. メモを畳む（昇格・破棄）

メモの内容が確定したら、必ず畳む。**放置しない。**

### 1. 昇格先を決める

| メモの内容 | 昇格先 | 使うスキル |
| --- | --- | --- |
| 案を比較して 1 つ選んだ | `docs/adr/` に ADR 起票 | `write-adr` |
| 実装が従うべき決まりごと | `docs/spec/` を更新 | `write-spec` |
| 手順・進め方 | `docs/guides/` | — |
| 不要になった | 破棄 | — |

### 2. 昇格先の文書を作る／更新する

### 3. メモを畳む

- 状態ヘッダを `昇格済み`（または `破棄`）に変更する
- `昇格先:` に昇格先ファイルへのリンクを書く
- **メモ本文は書き直さない。** 検討の跡としてそのまま残す
- ファイルを `docs/notes/archive/` へ移動する（`git mv` を使う）
- `docs/notes/README.md` の一覧から削除する

### 4. コミットする

```
docs(notes): <トピック> を <昇格先> へ昇格
```

## 判断に迷ったら

「これは notes に書くべきか、spec に書くべきか」で迷ったら **notes に書く。**
notes から spec への昇格は安全だが、未確定の記述が spec にあると
エージェントがそれを確定仕様として実装してしまう。

## チェックリスト

- [ ] ファイル名が `YYYY-MM-DD-` で始まっている
- [ ] 状態ヘッダがある
- [ ] 事実と推測が区別されている
- [ ] `docs/notes/README.md` の一覧を更新した
- [ ]（畳むとき）昇格先リンクを書き、archive へ移動した
